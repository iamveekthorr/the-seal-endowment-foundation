# CMS options for The Seals Endowment Foundation site

Ranked roughly from least to most technical to set up and run day-to-day.

| CMS | Technical difficulty | Pros | Cons |
|---|---|---|---|
| **Webflow** | Low — visual, drag-and-drop editor; no code to touch after setup | WYSIWYG editing staff can use directly; hosting, forms and CMS collections bundled together; clean designer tooling if someone later wants to refine the look | This exact hand-coded page has to be *rebuilt* inside Webflow's editor rather than just uploaded; billed monthly in USD, which is a recurring forex cost for a Nigeria-based foundation; Naira donation processing (Paystack/Flutterwave) isn't native — needs a workaround |
| **Wix** | Low — the easiest drag-and-drop option | Fastest to get a non-technical staffer publishing changes; cheap entry plans | Same rebuild-from-scratch problem as Webflow; least flexible if you want the design to stay pixel-close to this mockup; feels more "small business" than "endowment foundation" to donors |
| **WordPress** (+ Elementor/Bricks page builder, GiveWP or a Paystack/Flutterwave plugin for donations) | Low–medium to set up, low afterward | By far the largest pool of Nigerian developers and hosting providers who already know it, so it's the easiest to get local help for; this custom HTML/CSS can be wrapped into a WordPress theme largely as-is; mature donation, SEO and email-newsletter plugins; content editing afterward (news, events, programme cards) is genuinely easy for non-technical staff | Needs a host and ongoing updates/security maintenance (or a managed WP host that handles that for a fee); a developer is needed for the initial theme conversion |
| **Ghost** | Medium | Clean editor, good for news/updates and email newsletters to members; can be self-hosted cheaply | Built around blog/newsletter content more than a multi-section marketing homepage like this one; less natural fit for the "areas of focus" / "projects table" style sections; smaller Nigerian hosting/support ecosystem than WordPress |
| **Netlify CMS / Decap CMS** on top of a static site generator (e.g. Eleventy or Astro) | Medium–high to set up, low afterward | Keeps the design pixel-for-pixel exactly as built (no rebuild); free hosting (Netlify/Vercel/Cloudflare Pages); content is stored as simple files in Git, so there's a clean history of every edit; very fast, very secure (no database to hack) | Initial setup needs someone comfortable with Git and static site tooling; no built-in donation processing — you'd wire up Paystack/Flutterwave separately; less familiar to non-technical Nigerian freelancers than WordPress |
| **Headless CMS** (Sanity, Contentful, Strapi) + a custom-coded frontend | High | Most powerful and flexible option — the "index rows," "projects table," and "programme cards" map cleanly onto structured content models; excellent editing experience once built; scales well if the Foundation later wants an app or multiple sites pulling the same content | Requires a developer to build and maintain the frontend that fetches content from the API — the highest upfront cost of any option here; overkill unless there's a specific reason to outgrow WordPress |

## A practical recommendation

For a Nigeria-based foundation where the site will likely be maintained by staff or a part-time freelancer rather than an in-house engineering team, **WordPress** is the pragmatic middle ground: it's the option with the deepest local talent pool for both the initial build and ongoing tweaks, has mature Naira-friendly donation plugins, and can carry this exact design over largely unchanged. If keeping the design pixel-perfect and avoiding any hosting/maintenance burden matters more than easy local hires, **Netlify CMS on a static site** is the leaner technical alternative — same content, no database, and free hosting, at the cost of needing a developer for setup and for wiring up donations separately.
